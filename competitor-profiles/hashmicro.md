## What is worth learning

1. **Commercial breadth is explicit.** Visitors can land on a task, module, industry, AI use case, comparison, or pricing route without starting at the homepage.
2. **Product proof appears early.** Screens, UI previews, feature checklists, and an AI interaction demo sit beside the promise instead of being kept only for a later section.
3. **Lead capture is part of the architecture.** Forms ask for the minimum commercial context (contact, company, size, solution, industry, need) and repeat at decision points.
4. **Pricing has a concrete next step.** The offer page explains what is included in implementation, support, training, customization, and pricing simulation instead of leaving a visitor with a generic contact link.
5. **Comparison is an acquisition surface.** The sitemap includes many comparison routes, so a visitor who is already evaluating alternatives has a relevant page.

## Guardrails when benchmarking

- These are observations from public pages, not proof that every advertised module is active for every account.
- Do not copy HashMicro visual assets, copy, logos, or claims into RAMUNI. Use the benchmark only for information architecture and proof density.
- RAMUNI should show a real or clearly labelled demo screen, a concrete input → output explanation, package boundaries, and a direct CTA on each money page.
